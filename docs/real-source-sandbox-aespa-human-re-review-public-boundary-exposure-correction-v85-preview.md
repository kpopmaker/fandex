# AESPA human re-review public boundary exposure correction (v85)

V85 is an additive public-interface correction, not a submission stage. Two earlier attempts correctly stopped: v84's public input omitted three upstream safety boundaries, and the complete future-submission audit then found that the tracked validator also requires target-specific `gate_status`. Reading v84's retained v83 packet would have violated the private-state boundary, while inferring status from `gate_id` would have invented semantics.

V85 therefore builds a fresh real v84 public blank input and a separate fresh real v83 public packet. It proves exact packet ID, request ID, seven-field target identity, gate ID, and historical-decision compatibility before composition. It never reads a private attribute from v84, v83, v82, or v81.

The tracked v73 explicit-human-shadow-decision contract is the gate authority. Its `target_safe_lineage.gate_id` exactly equals the public v83/v84 gate ID, and its `historical_before_expectations.gate_status` supplies `exception_review_required`. The gate vocabulary comes from `human_review_decision_contract.preview.json::gate_status_rules`. The tracked `validate_human_review_decisions.py::validate_entry` call requires `gate_status`; V85 records that dependency but does not copy or execute its decision/gate logic.

The corrected closed view preserves all 15 v84 fields byte-for-semantic-value and in schema order, including the original `decision_input_id`. It appends exactly four fields: `synthetic_shadow` from `v83.shadow_fulfillment_summary.synthetic_shadow`, `external_verification_performed` from `v83.shadow_fulfillment_summary.external_verification_performed`, `real_historical_enrichment_request_fulfilled` from the matching v83 top-level field, and `gate_status` from the tracked gate authority bound by public gate ID. It embeds neither the v83 packet, the gate object, nor validator contracts, and exposes no fifth semantic boundary.

The real corrected view has `synthetic_shadow = true`, `external_verification_performed = false`, `real_historical_enrichment_request_fulfilled = false`, and `gate_status = exception_review_required`. These are contextual facts, not decision signals. `not_decided` remains the authority-defined blank placeholder; the reviewer and reviewed-at values remain null, rationale remains empty, no decision is preselected or submitted, and recommendation remains null. Historical `request_enrichment` remains unchanged.

The future-v86 dependency registry audits public template status and lineage, blank human fields, decision boundaries, review context, the four corrected fields, safe effect counters, and direct access to the immutable validator/input/application contracts. Future human-entered values are correctly classified as future explicit input rather than hidden upstream state. Every required dependency is publicly resolved, tracked-authority resolved, or explicitly future-human supplied; unresolved and post-v85 private-state dependency counts are zero.

Mismatch in prerequisites, lineage, gate binding, authority vocabulary, any boundary, preservation, effect counter, dependency closure, or projection scope fails closed without retry or mutation. Negative doubles are limited to impossible upstream failures. Two complete successes use fresh real v83 and v84 executions and produce identical corrected views, gate bindings, dependency registries, and canonical hashes. All consumed authorities, transitively loaded v81/v82 files, and Last.fm files remain byte-identical.

V85 does not submit a human decision. V85 does not select a decision. V85 does not change `not_decided` blank semantics. V85 does not modify v84 authority files. V85 does not inspect v84 private retained v83 state. V85 obtains the three shadow boundary values only from a real v83 public packet. V85 obtains gate status only from tracked authority bound by public gate ID. V85 does not externally verify evidence, fulfill the real historical enrichment request, or change historical `request_enrichment`.

With conformance passed, v86 may consume this corrected public view and reuse the tracked validator for an explicit controlled shadow submission. V86 must still perform no historical mutation, real submission, application, audit write, or production effect. V86 is not implemented here.
