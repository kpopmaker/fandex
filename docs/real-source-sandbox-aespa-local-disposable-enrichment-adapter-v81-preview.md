# AESPA local disposable enrichment adapter preview (v81)

V81 is the reusable process-local adapter implementation. V75 defines the executable fulfillment baseline; v76 makes planning read-only and fixes duplicate collision ordering; v77 makes satisfied evaluation explicitly idempotent; v78 supplies closed executable schemas; v79 supplies deterministic planning policy; and v80 permits consecutive valid evidence accumulation while a field remains `evidence_available`. Later authority wins only for its explicit correction.

`LocalDisposableEnrichmentAdapter` owns all semantic state inside one Python instance. It uses dictionaries and deep-copy candidate replacement, has no singleton or mutable module-global semantic store, and uses no database, network, environment-dependent semantics, or filesystem persistence. Importing the module runs no CLI or self-test work.

The six public operations are `inspect_enrichment_satisfaction`, `build_enrichment_fulfillment_plan`, `validate_enrichment_evidence`, `accept_controlled_enrichment_evidence`, `evaluate_enrichment_completion`, and `read_shadow_fulfillment_result`. Initialization enforces the closed seven-field v78 schema, canonical requested fields, the seven-field immutable target identity, `not_authorized`, requested lifecycle, sorted local evidence, and a recomputed request ID.

Request and evidence identities use canonical UTF-8 JSON with sorted keys, compact separators, one trailing LF, SHA-256, and lowercase hex. Content digests use NFC normalization, surrounding trim, UTF-8, and SHA-256 without an appended newline. Adapter-facing objects are validated without coercion or unknown fields.

Inspection is read-only. Planning implements all twelve `fulfillment_plan_v75` fields and the v79 pure derivation. Missing content is represented as required title plus a canonical `one_of(summary, bounded_excerpt)`, not as two mandatory alternatives. Local candidates are filtered in the order `existing_local_normalized`, `controlled_fixture_input`; external candidates never appear while not authorized. Progress operations are deterministically accept then evaluate. Planning never persists `planned`, never mutates semantic state, and repeats byte-identically for identical state.

Validation is stateless with respect to accepted-evidence collisions. Acceptance performs prerequisite and binding checks, then stored-ID collision classification. Exact duplicates are idempotent no-ops; changed payloads with the same stored ID are `conflicting_duplicate`; only non-colliding evidence undergoes strict identity verification. Existing valid local evidence has precedence. Locators are checked with the exact authority regexes and never dereferenced. Full article body retention is prohibited.

Controlled fixtures are the only executable acceptance class. The v80 transition permits title followed by summary or bounded excerpt without forced evaluation: `evidence_available` remains `evidence_available`, lifecycle change is false, evidence change is true, and operation mutation is true. Acceptance is field-isolated and never auto-evaluates. A satisfied field rejects further controlled acceptance; unavailable and failed remain unreachable locally.

Content completion is title plus summary or bounded excerpt. Bounded excerpts are NFC-normalized, trimmed, and limited to 1000 Unicode code points. Attribution requires `author_or_publisher`; provider or hostname context alone is insufficient. Evaluation examines every requested field using the v77 matrix, supports a satisfied no-op alongside another field's mutating transition, and makes repeated full evaluation a zero-mutation non-regressing operation.

The safe result is the closed v78 snapshot: safe evidence metadata only, detached by deep copy, with `human_re_review_required = true`. Mutating returned inspection, plan, or result objects cannot modify adapter state.

The real-target proof uses only the tracked empty local evidence and performs no fixture acceptance. The separate controlled shadow flow accepts deterministic synthetic title, summary, and attribution evidence, evaluates to a satisfied shadow request, and still requires human re-review. Alternate title-plus-excerpt and three-evidence flows also pass. The v79 planning and v80 acceptance matrices are replayed against the implementation with zero mismatches. Separate A, B, and C instances prove isolation and disposability.

V81 does not retrieve the MyDaily article. V81 does not call Naver. V81 performs no external retrieval. V81 controlled fixtures are synthetic local shadow evidence only. V81 does not fulfill the real human enrichment request, mutate historical AESPA state, or approve or reject anything. V81 semantic adapter state exists only in process memory. Authority, historical, and Last.fm files remain byte-identical; all real, external, database, persistence, scoring, ranking, chart, public-data, and production effect counters remain zero.

Independent first/reproduction artifacts prove deterministic behavior. With conformance passed, v82 may separately implement a local fulfillment orchestrator that composes the read-only target, v81 adapter, deterministic plan, controlled acceptance, evaluation, and mandatory human re-review. V82 is not implemented here.
